# Поиск по текстам документов

Небольшой поисковый сервис: документы лежат в PostgreSQL, полнотекстовый индекс — в Elasticsearch. Сервис ищет по тексту и отдаёт не больше 20 совпадений со всеми полями базы, от новых к старым. Удаление убирает документ и из базы, и из индекса.

Стек: FastAPI, SQLAlchemy 2 (async), asyncpg, Elasticsearch 8. Всё асинхронное, поднимается одной командой Docker Compose.

## Как устроен поиск

Индекс по заданию хранит только `id` и `text`. Даты в нём нет, поэтому порядок «по дате создания» нельзя честно получить сортировкой Elasticsearch.

Запрос выполняется в два шага:

1. Elasticsearch (встроенный анализатор `russian`) находит id документов, где встретились все слова запроса.
2. PostgreSQL выбирает эти id и возвращает 20 строк с самой поздней `created_date`.

Если взять из Elasticsearch только топ по релевантности и пересортировать его по дате, старый документ с высоким BM25 вытеснит более новый. Сервис так не делает: в базу уходят все id совпадений (окно — 10 000, в массиве 1 500 документов). Если совпадений больше окна, сервис отвечает ошибкой, а не неполной выдачей.

Удаление сначала убирает документ из индекса, затем из базы. Поиск читает поля только из PostgreSQL, поэтому строка, которой уже нет в базе, не попадёт в ответ. Если процесс оборвётся между двумя удалениями, при следующем старте сервис сравнивает число документов и пересобирает индекс.

В исходном CSV нет колонки `id`. Идентификатор — номер строки, начиная с 1. Этот номер стабилен и используется в удалении.

## Запуск

Нужны Docker и Docker Compose.

```bash
docker compose up --build
```

Первый запуск собирает Elasticsearch 8.15.3 из официального архива (около 600 МБ). Образы не скачиваются с `docker.elastic.co`: этот реестр обрывает соединение. База образов — уже имеющийся Debian (`postgres`).

Страница поиска: http://localhost:8000  
Swagger: http://localhost:8000/docs  
OpenAPI-файл из репозитория: http://localhost:8000/docs.json и `docs.json` в корне.

Первый старт загружает `data/posts.csv` (1500 документов) в базу и в индекс. Повторный старт данные не дублирует. Чтобы загрузить массив заново:

```bash
docker compose down -v
docker compose up --build
```

### Примеры

Поиск:

```bash
curl "http://localhost:8000/documents/search?text=конкурс"
```

Ответ — JSON-массив, не длиннее 20 элементов, поля `id`, `rubrics`, `text`, `created_date`, порядок от новых к старым.

Удаление:

```bash
curl -X DELETE "http://localhost:8000/documents/1"
```

`204` — документ удалён. Повторный вызов и неизвестный id возвращают `404`.

## Тесты

Функциональные тесты ходят в настоящие PostgreSQL и Elasticsearch (отдельная база `search_test` и индекс `documents_test`).

```bash
docker compose --profile test run --rm tests
```

Локально, когда Postgres и Elasticsearch уже опубликованы на `localhost:5432` и `localhost:9200`:

```bash
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt
.venv/Scripts/pytest
```

На Linux и macOS те же команды через `.venv/bin/`.

Отдельная проверка разбора CSV не требует сервисов: `pytest tests/test_loader.py`.

## Методы

| Метод | Путь | Что делает |
| --- | --- | --- |
| GET | `/documents/search?text=` | Поиск, максимум 20 документов |
| DELETE | `/documents/{id}` | Удаление из базы и индекса |
| GET | `/health` | Проверка PostgreSQL и Elasticsearch |

Пустой `text` — `422`. Если индекс или база недоступны — `503`.

## Структура

```
app/            сервис: API, база, индекс, загрузка CSV
data/posts.csv  тестовый массив
tests/          разбор CSV и функциональные тесты поиска и удаления
docs.json       OpenAPI
```

Переменные окружения перечислены в `.env.example`. В Compose они уже заданы.
